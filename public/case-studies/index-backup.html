DATA MIGRATION

Snowflake to Databricks Migration

A fintech company needed to migrate their entire data warehouse from Snowflake to Databricks. 50+ tables, complex transformations, and zero tolerance for data discrepancies.

The Problem

The client's Snowflake costs had grown 3x year-over-year. Their data science team wanted Databricks for ML workloads, but the finance team wouldn't pay for both platforms. They needed a complete migration with:

  • Zero downtime during transition
  • Bit-perfect data validation
  • Translated SQL queries and stored procedures
  • Maintained downstream dependencies

Constraints

This wasn't a greenfield project. Real-world constraints included:

  • Production dashboards couldn't break
  • Some queries used Snowflake-specific functions
  • Team had limited Spark experience
  • Compliance required audit trail of all data
  • Budget for external help was fixed

Approach

I built a phased migration with parallel running:

  1. Audited all 50+ tables and documented dependencies
  2. Built reconciliation framework to compare source and target
  3. Migrated schemas and historical data in batches
  4. Converted SQL queries to Spark-compatible versions
  5. Ran both systems in parallel for 2 weeks
  6. Cut over after validation passed

The reconciliation framework was the key deliverable. It automated:

  • Row count comparisons per table
  • Aggregate value checks (sums, averages)
  • Sample-based row-level comparisons
  • Schema drift detection
  • Daily reconciliation reports

From 15 Hours to Zero: Automated Executive Reporting

A B2B wholesale distributor was drowning in manual reporting. Their operations manager spent 15+ hours per week pulling data from 4 different systems just to create a weekly performance deck.

The Problem

Every Monday morning, leadership expected a weekly performance deck. Creating it required:

  • Exporting CSVs from Shopify (orders, inventory)
  • Pulling financials from QuickBooks
  • Getting fulfillment data from ShipStation
  • Querying a legacy Access database for customer data
  • Copy-pasting everything into Excel with VLOOKUPs
  • Manually creating charts and emailing PDFs

The Pain

  • Reports were always late (Tuesday or Wednesday)
  • Frequent errors from copy-paste mistakes
  • Couldn't answer ad-hoc questions without starting over
  • Operations manager was a bottleneck (vacation = no reports)
  • No historical visibility - last week's data was gone
  • Leadership frustrated with stale, unreliable numbers

Approach

I built an automated data pipeline that eliminated manual work entirely:

Data Pipeline
  1. Scheduled API extracts from all 4 sources
  2. Data validation and cleaning layer
  3. Loaded into a simple PostgreSQL database
  4. Historical snapshots preserved automatically
  5. Incremental updates (only changed data)
Reporting Layer
  1. Metabase dashboards (auto-refreshed daily)
  2. Self-service filters for ad-hoc questions
  3. Automated PDF export every Monday 6am
  4. Email delivery to all stakeholders
  5. Slack notification on completion

Incremental Product Data Feed

An e-commerce analytics company needed daily product data from multiple retail sources. Full refreshes were too slow and expensive. They needed incremental updates with change tracking.

The Problem

The existing approach had multiple issues:

  • Full crawls taking 8+ hours daily
  • No way to know what changed between runs
  • Scrapers breaking without notification
  • Historical data being overwritten
  • API rate limits being hit constantly

Constraints

  • Must respect robots.txt and rate limits
  • Data needed by 8am daily for client reports
  • Budget for compute was fixed
  • Some sources had anti-bot protection
  • Change history needed for analysis

Approach

I built an incremental crawling system with change detection:

Incremental Strategy
  • Hash-based change detection per product
  • Priority queue: new/changed items first
  • Smart scheduling based on update frequency
  • Full refresh only weekly for verification
  • Delta files for downstream processing
Reliability Features
  • Automatic retry with exponential backoff
  • Proxy rotation for rate limit management
  • Health checks every 15 minutes
  • Slack alerts for failures
  • Dead letter queue for failed items
